## Top gaps

### P0
1. **Android — error/blocked states lost on main card.** `ConnectionProxy.tunnelState` maps both `Failed` and `Blocking` (kill switch) to `TunnelState.Disconnected` (`ConnectionProxy.kt:54-61`). The connection card therefore shows "DISCONNECTED" (red) when the tunnel actually failed or is in kill-switch blocking. The real state ("Failed: <reason>", "Blocking internet (kill switch)") is only visible as a transient snackbar and a small top overlay banner. Desktop and iOS both render a distinct blocked/error status on the main surface. This is a privacy/safety-relevant UX gap: a user can believe they are simply disconnected when the kill switch is actively blocking, or miss a tunnel failure.
2. **Android — lossy state pipeline for the main card.** Because the card is still driven by the back-compat `ConnectionProxy` (Mullvad-shaped) with a sentinel endpoint, the main card cannot show DAITA, multihop, obfuscation, In/Out IP, port, or protocol — all of which exist in the underlying Warren state. The card is effectively a downgraded view; the authoritative state is shunted to ephemeral banners/snackbars. Recommend feeding the card a Warren-native state (real endpoint + feature flags) so the existing chip/detail UI populates.

### P1
3. **Android — Connection details In/Out IP not populated on card.** Render code (`ConnectionDetailPanel.kt`) is correct but fed the sentinel `0.0.0.0:0` endpoint (`ConnectionProxy.kt:38-46`). Out IP comes only from geoip `location()`. Desktop and iOS show real in-address (ip:port proto) and out IPv4/IPv6.
4. **Android — DAITA / Multihop / Obfuscation chips never render.** The chip components exist and work, but the feeding `TunnelState.Connected` has `daita=false`, `obfuscation=null`, no entry endpoint. These features are present in the Warren state string (`WarrenQuinnStateProxy.kt:66-73`) but only as banner text, not as structured chips. Desktop and iOS render them as first-class indicators.
5. **Obfuscation/mimicry indicator parity.** Desktop has explicit "HTTP/3 mimicry (active)" detail rows; iOS has a dedicated `WarrenObfuscationIndicatorView` in expanded details. Android only embeds "mimicry" as a token inside the overlay banner string — no equivalent card/detail UI.

### P2 / polish
6. **Android — three overlapping state surfaces** (snackbar `"Warren: $state"` + top banner + the card itself) are redundant and were explicitly noted as temporary scaffolding (D.4 step 13/20). Consolidate once the card reads Warren-native state.
7. **Warren status rows (reconnect count / last-reconnect age) are desktop-only** (`ConnectionDetails.tsx:120-155`). Neither mobile platform surfaces a reconnect counter. Low priority.

## Cross-platform posture
- **iOS**: near-full parity. It retains the entire upstream Mullvad connection panel (map, chips, in/out IP, all status states, reconnect split-button) and adds the Warren obfuscation banner. Strongest of the two mobile targets for this domain.
- **Android**: the UI shell is at parity (map/globe, chips, detail panel, buttons all exist and match upstream), but the **data pipeline into the main card is lossy** — error/blocked/kill-switch states and the DAITA/multihop/obfuscation/IP details do not reach the card and are only shown in temporary banners. This is the dominant gap cluster for this domain.
