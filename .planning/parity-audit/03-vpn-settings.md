# Parity Audit 03 — VPN / Tunnel Settings

**Reference:** Electron desktop (`desktop/packages/mullvad-vpn/`)
**Targets:** Android (`android/`), iOS (`ios/`)
**Scope:** User-facing VPN/tunnel settings + UX parity (not implementation).
**Date:** 2026-05-31

## Architecture context

- **Desktop** splits VPN settings across the *Settings* menu (`SettingsView.tsx`) — DAITA, Warren multi-hop, Port forwarding, Split tunneling each get their own list-item/route — plus a combined *VPN settings* view (`VpnSettingsView.tsx`) holding auto-start/auto-connect, LAN, DNS, IPv6, kill switch, anti-censorship, quantum-resistant, IP version, MTU, IP overrides.
- **Android** funnels DAITA / multi-hop / NAT-PMP / IPv6 / kill switch / DNS / content blockers into **one** Warren-native screen `WarrenTunnelSettings` (the legacy "VPN settings"/Multihop/DAITA menu cells all route here — `SettingsScreen.kt:101,120,122,130`). Split tunneling keeps its own native screen. Config is built solely from `WarrenLocalSettingsRepository` via `WarrenTunnelConfigBuilder` (legacy proto settings are dead).
- **iOS** keeps the legacy Mullvad `VPNSettingsDataSource` (DNS, IP overrides, QUIC port, QUIC obfuscation [read-only], quantum resistance, IP version) **plus** separate Warren SwiftUI scaffolds (DAITA, Multihop, NAT-PMP). Kill switch / LAN / auto-connect ride on the NE tunnel config (`TunnelConfiguration.swift`) via the *IncludeAllNetworks* screen + on-demand rules.

## Top gaps (by severity)

### P0 — dead toggles shipping to users (iOS)
1. **iOS DAITA toggle is non-functional** (`WarrenDaitaSettingsView.swift:53-57`). The switch flips UI state only; `onChange` is `_ = newValue` with a TODO. User believes DAITA is on; tunnel never receives it. Android+desktop both fully wire it.
2. **iOS NAT-PMP / port forwarding is non-functional** (`WarrenNatPmpSettingsView.swift:56-61, 81-87`). Toggle does nothing, port status is placeholder, no App-Group persistence, no FFI. Desktop+Android ship full functional port forwarding (Warren's flagship differentiator).

### P1 — missing/misleading user-facing settings
3. **iOS still exposes legacy WireGuard pickers** as live controls: selectable "QUIC port" / custom port and the full obfuscation picker (Shadowsocks, udp-over-tcp, QUIC, LWO, off) that dispatch `TunnelSettingsUpdate.obfuscation` (`VPNSettingsDataSource.swift:340-357`). For Warren (always-QUIC + always-on M4.0 mimicry) these are dead/misleading. Desktop+Android correctly hide the obfuscation picker and show a read-only mimicry indicator; iOS does this inconsistently (omits from list at L494-499 but keeps the dedicated route live).
4. **iOS content blockers (6 categories) entirely absent.** Desktop+Android expose ads/trackers/malware/adult/gambling/social. iOS DNS UI is custom-resolver only.
5. **iOS multi-hop likely dead-ends:** `SettingsMultihopView` mutates legacy `MultihopState` in `WarrenSettings`, not the Warren QUIC tunnel config path — needs verification that the PacketTunnel actually reads it (Android reads `multiHopEnabled` directly into the builder).
6. **Android auto-connect/lockdown settings screen is orphaned:** `AutoConnectAndLockdownMode` + `AutoConnectNavKey`/`AutoConnectEntryProvider` exist but nothing navigates to them; meanwhile `AutoStartVpnBootCompletedReceiver` auto-connects on boot with no user-facing gate. Desktop has explicit auto-start/auto-connect toggles.
7. **Android LAN/local-network sharing not user-controllable:** `allowLan` lives only in dead legacy `lib/model/Settings.kt`; not in `WarrenLocalSettingsRepository`, not read by `WarrenTunnelConfigBuilder`. Desktop has `AllowLanSetting`; iOS has `excludeLocalNetworks`.

### P2 — minor gaps / cross-platform inconsistency
8. **MTU**: desktop-only. Neither mobile exposes it (Android has an unwired `MtuListItem`).
9. **DAITA direct-only**: desktop-only sub-toggle.
10. **Quantum-resistant tunnel**: present+active on desktop (`default-settings.ts:39` default `true`, relabeled "QUIC tunnel") and a live picker on iOS, but absent on Android — and its actual applicability to Warren's QUIC transport is unverified (this is a leftover Mullvad WireGuard PQ setting; likely should be intentionally removed or documented, not silently toggling per-platform).
11. **IPv6**: desktop+Android offer a Warren IPv6-leak toggle; iOS only has the legacy auto/v4/v6 IP-version picker (different semantics).

## Cross-cutting observations
- Android's Warren tunnel surface (`WarrenTunnelSettings` + `WarrenLocalSettingsRepository` + `WarrenTunnelConfigBuilder`) is the **most complete and correctly wired** mobile parity layer — every visible toggle reaches the connect-time config.
- iOS is the weakest: two flagship toggles (DAITA, NAT-PMP) are dead scaffolds, content blockers are missing, and legacy WireGuard/obfuscation pickers remain live and misleading.
- The desktop "VPN settings" view itself contains no DAITA/multihop/port-forwarding (those are top-level menu entries); Android consolidates them, iOS scatters them. Functionally equivalent grouping is acceptable; the gaps are about wiring and missing features, not layout.
